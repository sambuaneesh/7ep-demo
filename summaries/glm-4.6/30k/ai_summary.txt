
# Comprehensive Architectural Summary

## Core Application Architecture

### **Framework & Runtime**
- **Language/Framework**: Java-based monolithic web application using Java Servlets
- **Build System**: Gradle 7.0 (with wrapper scripts `gradlew`)
- **Application Server**: Apache Tomcat 9 (configured in `web.xml`)
- **Frontend**: Static HTML/CSS/JS files in `src/main/webapp` with server-side rendering via JSP (`result.jsp`, `restfulresult.jsp`)
- **Hot Swap**: Gretty plugin for development

### **Database & Persistence**
- **Primary Database**: H2 in-memory database with file-based mode for persistence
  - Connection: `jdbc:h2:./build/db/training` (unit tests use `build/db/training.mv.db`)
  - PostgreSQL compatibility mode enabled
- **Migration Management**: FlywayDB with versioned scripts in `src/main/resources/db/migration/`
  - Schema migrations: `V1__Create_person_table.sql`, `V2__Rest_of_tables_for_auth_and_library.sql`
  - Runtime management via `DbServlet` (`/flyway` endpoint)
- **Persistence Architecture**:
  - Interface: `IPersistenceLayer.java`
  - Implementation: `PersistenceLayer.java` (uses `SqlData.java` for query execution)
  - Custom micro-ORM with type-safe parameter binding (`ParameterObject`)
  - Null object pattern: `EmptyDataSource` for testing

## Key Business Domains & Components

### 1. **Authentication System**
**Components:**
- `LoginServlet.java` - Handles user authentication (`/login`)
- `RegisterServlet.java` - Handles user registration (`/register`)
- `LoginUtils.java` - Credential validation business logic
- `RegistrationUtils.java` - User registration with password validation (Nbvcxz library)

**Domain Objects:**
- `User.java` - User entity (id, name, password_hash)
- `RegistrationResult.java` - Registration outcome status
- `PasswordResult.java` - Password security metrics (entropy, crack time)
- `PasswordResultEnums` - Password validation result types

**Security Features:**
- Password entropy validation via `RegistrationUtils.isPasswordGood()`
- SHA-256 password hashing (BCrypt implied)
- Custom validation with result enums

### 2. **Library Management System**
**Servlets:**
- `LibraryRegisterBookServlet.java` - Book registration (`/registerbook`)
- `LibraryRegisterBorrowerServlet.java` - Borrower registration (`/registerborrower`)
- `LibraryLendServlet.java` - Book lending operations (`/lend`)
- `LibraryBookListAvailableServlet.java` - List available books (`/listavailable`)
- `LibraryBookListSearchServlet.java` - Book CRUD/search (`/book`)
- `LibraryBorrowerListSearchServlet.java` - Borrower CRUD/search (`/borrower`)

**Business Logic:**
- `LibraryUtils.java` - Validates lending rules and library operations
- Domain objects: `Book.java`, `Borrower.java`, `Loan.java`
- Operation results: `LibraryActionResults.java`

### 3. **Mathematics Service**
**Servlets & Logic:**
- `MathServlet.java` - Basic arithmetic operations (`/demo/math`)
- `FibServlet.java` - Fibonacci number calculation
- `AckServlet.java` - Ackermann function computation
- Core implementations: `Calculator.java`, `Fibonacci.java`, `Ackermann.java`
- Iterative implementations for performance optimization

**Algorithm Selection:**
- Request parameter `algorithm_choice` selects recursive/iterative variants
- Input validation: Rejects non-integer inputs and large numbers

### 4. **Expense Calculation**
- `AlcoholCalculator.java` - Estimates alcohol costs for restaurant bills
- Domain objects: `AlcoholResult.java`, `DinnerPrices.java`

### 5. **Desktop Application (Auto Insurance)**
**Components:**
- `AutoInsuranceUI.java` - Swing-based user interface
- `AutoInsuranceProcessor.java` - Premium calculation logic
- `AutoInsuranceScriptServer.java` - Socket-based test control (port 8000)

**Domain Objects:**
- `AutoInsuranceAction.java` - Premium calculation outcomes
- `WarningLetterEnum.java` - Warning level definitions

## Database Schema & Data Models

### **Schema Structure**
```sql
-- AUTH Schema
CREATE TABLE USER (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  password_hash VARCHAR(100)
);

-- LIBRARY Schema
CREATE TABLE BOOK (
  id SERIAL PRIMARY KEY,
  title VARCHAR(100) NOT NULL
);

CREATE TABLE BORROWER (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL
);

CREATE TABLE LOAN (
  id SERIAL PRIMARY KEY,
  book INT REFERENCES BOOK(id),
  borrower INT REFERENCES BORROWER(id),
  borrow_date DATE NOT NULL
);

-- ADMINISTRATIVE Schema
-- Flyway schema history table
```

### **Domain Object Specifications**
| **Entity** | **Key Fields** | **Methods** |
|------------|----------------|-------------|
| `Book` | id, title | `createEmpty()`, `toString()` |
| `Borrower` | id, name | `createEmpty()`, `toOutputString()` |
| `Loan` | id, book, borrower, borrow_date | `createEmpty()` |
| `User` | id, name, password_hash | - |

**Relationships:**
- `LOAN.BOOK` → `BOOK.ID` (foreign key)
- `LOAN.BORROWER` → `BORROWER.ID` (foreign key)

## Architectural Patterns & Frameworks

### **Design Patterns**
1. **Layered Architecture:**
   - Web Layer (Servlets) → Business Logic (Utils) → Persistence Layer → Database
   
2. **Domain-Driven Design:**
   - Immutable domain objects with validation
   - Business logic separated by domain (`com.coveros.training.library`, `authentication`)
   
3. **Micro-ORM Pattern:**
   - Custom SQL execution framework (`SqlData`, `ParameterObject`)
   - Type-safe parameter binding with functional interfaces
   
4. **Null Object Pattern:**
   - `EmptyDataSource` for testing scenarios

### **Dependency Management**
- Manual dependency injection via constructors
- Example: `LoginUtils`, `LibraryUtils` receive `IPersistenceLayer`

### **Frontend Architecture**
- SPA patterns implemented in `library.js`, `catalog.js`
- Server-side rendering with JSPs for result display

## Microservice Decomposition Insights

### **Candidate Services**
1. **Authentication Service:**
   - Scope: User registration, login, password policies
   - Endpoints: `/login`, `/register`
   - Database: `AUTH.USER` table
   - Business logic: `LoginUtils`, `RegistrationUtils`

2. **Library Service:**
   - Scope: Book/borrower CRUD, lending, availability
   - Endpoints: `/book`, `/borrower`, `/lend`, `/listavailable`
   - Database: `LIBRARY.*` tables
   - Business logic: `LibraryUtils`

3. **Mathematics Service:**
   - Scope: Pure computations (Ackermann, Fibonacci, arithmetic)
   - Stateless processing
   - Algorithm selection via parameters

4. **Insurance Service:**
   - Scope: Premium calculations, warning letters
   - Components: `AutoInsuranceProcessor`, `AutoInsuranceUI`

5. **Database Migration Service:**
   - Scope: Flyway management, schema versioning
   - Endpoint: `/flyway`

### **Decomposition Considerations**
1. **Data Separation:**
   - Schemas already separated by domain
   - Each service could have its own database instance
   
2. **API Refactoring:**
   - Convert servlets to RESTful APIs (Spring Boot)
   - Implement DTOs for request/response
   
3. **Frontend Decoupling:**
   - Extract JavaScript to SPA (React/Vue)
   - Implement API gateway pattern
   
4. **Shared Components:**
   - Persistence layer as shared service or library
   - Common utilities (`ServletUtils`, `StringUtils`, `CheckUtils`)

5. **Testing Strategy:**
   - Contract testing for service boundaries
   - Maintain multi-language UI test suite
