### Comprehensive Architectural Summary

#### **Core Application Architecture**
- **Framework**: Java-based monolithic web application using **Java Servlets** with **Gradle** as build system
- **Runtime**: Apache Tomcat server (configured in `web.xml`)
- **Frontend**: Static HTML/CSS/JS files in `src/main/webapp` with server-side rendering via JSP (`result.jsp`)
- **Database**: H2 in-memory database with Flyway migrations (`src/main/resources/db/migration/`)

---

### **Key Business Domains & Components**

#### 1. **Authentication System**
- **Servlets**: 
  - `LoginServlet.java` (handles user login)
  - `RegisterServlet.java` (handles user registration)
- **Domain Objects**:
  - `User.java` (user entity)
  - `RegistrationResult.java` & `PasswordResult.java` (operation outcomes)
- **Utilities**: 
  - `LoginUtils.java` & `RegistrationUtils.java` (validation/password hashing)
- **Security**: Custom password validation with result enums (`PasswordResultEnums`)

#### 2. **Library Management System**
- **Servlets**:
  - `LibraryRegisterBookServlet.java` & `LibraryRegisterBorrowerServlet.java`
  - `LibraryLendServlet.java` (book lending)
  - Search/listing servlets for books/borrowers
- **Domain Objects**:
  - `Book.java`, `Borrower.java`, `Loan.java`
  - `LibraryActionResults.java` (operation status)
- **Business Logic**: `LibraryUtils.java` (validates lending rules)

#### 3. **Mathematics Service**
- **Servlets**: 
  - `MathServlet.java` (basic calculations)
  - `FibServlet.java` (Fibonacci numbers)
  - `AckServlet.java` (Ackermann function)
- **Core Logic**:
  - `Calculator.java`, `Fibonacci.java`, `Ackermann.java`
  - Iterative implementations for performance
- **Error Handling**: Rejects non-integer inputs/large numbers

#### 4. **Expense Calculation**
- **Logic**: `AlcoholCalculator.java` (estimates alcohol costs)
- **Domain**: `AlcoholResult.java`, `DinnerPrices.java`

#### 5. **Desktop Application (Auto Insurance)**
- **UI**: Swing-based (`AutoInsuranceUI.java`)
- **Business Logic**: `AutoInsuranceProcessor.java` (premium calculations)
- **Automation**: `AutoInsuranceScriptServer.java` (socket-based test control on port 8000)
- **Domain**: 
  - `AutoInsuranceAction.java` (premium outcome)
  - `WarningLetterEnum.java` (warning levels)

---

### **Data Persistence Layer**
- **Interface**: `IPersistenceLayer.java`
- **Implementation**: `PersistenceLayer.java` (uses `SqlData.java` for query execution)
- **Database Schema**:
  - Tables: `person`, `book`, `borrower`, `loan`

   - **Library Service**: Manages books, borrowers, loans  
   - **Math Service**: Provides calculation algorithms  
   - **Auth Service**: Handles user registration/login  
   - **Database Migration Service**: Flyway management  

2. **Decompression Points**  
   - Servlet endpoints → RESTful microservice APIs  
   - Domain objects → Shared libraries between services  
   - UI tests → Contract testing across service boundaries  

3. **Data Flow**  
   ```mermaid
   Client → UI → Servlet → Service → Persistence
              ↓
        Selenium/Behave Tests
   ```

4. **Key Considerations**  
   - Stateless servlets enable easy containerization  
   - Algorithm selection (recursive/iterative) suitable for feature flags  
   - UI test suite validates service integration end-to-end  

This summary preserves critical architectural details for analyzing service boundaries, API contracts, and deployment topology in a microservices migration.
