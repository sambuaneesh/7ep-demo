# Architectural Summary for Microservice Decomposition Analysis

## 1. System Overview
This codebase represents a comprehensive library management system with authentication, mathematical utilities, and restaurant expense calculation capabilities. The application follows a layered architecture with clear separation between web, business logic, and persistence layers.

## 2. Core Components and Responsibilities

### 2.1 Authentication Domain
**Components:**
- `LoginServlet` - Handles user authentication via POST /login
- `RegisterServlet` - Manages user registration via POST /register
- `LoginUtils` - Validates user credentials against database
- `RegistrationUtils` - Processes new user registrations with password validation

**Key Business Logic:**
- Password strength validation using Nbvcxz entropy analysis
- SHA-256 password hashing
- Username uniqueness validation
- Credential verification

### 2.2 Library Management Domain
**Components:**
- `LibraryUtils` - Core library business logic
- `LibraryRegisterBookServlet` - POST /registerbook
- `LibraryRegisterBorrowerServlet` - POST /registerborrower  
- `LibraryLendServlet` - POST /lend
- `LibraryBookListSearchServlet` - GET /book
- `LibraryBorrowerListSearchServlet` - GET /borrower
- `LibraryBookListAvailableServlet` - GET /listavailable

**Key Business Logic:**
- Book availability checking
- Loan validation and creation
- Borrower registration validation
- Book registration with duplicate prevention

### 2.3 Mathematics Domain
**Components:**
- `MathServlet` - POST /math (basic addition)
- `FibServlet` - POST /fibonacci (multiple algorithm implementations)
- `AckServlet` - POST /ackermann (multiple algorithm implementations)
- `Calculator` - Basic arithmetic operations
- `Fibonacci` / `FibonacciIterative` - Mathematical sequence calculations
- `Ackermann` / `AckermannIterative` - Complex recursive function calculations

**Algorithms:**
- Recursive Fibonacci
- Iterative Fibonacci (O(log(n)) and linear)
- Recursive Ackermann
- Tail-recursive Ackermann

### 2.4 Persistence Layer
**Components:**
- `PersistenceLayer` - Implements IPersistenceLayer interface
- `DbServlet` - GET /flyway (database management)
- `SqlData` - Micro-ORM implementation
- `ParameterObject` - SQL parameter handling

### 2.5 Helper Components
**Components:**
- `ServletUtils` - Request forwarding and response handling

# Architectural Summary - Codebase Chunk 3

## Overview
This chunk contains comprehensive test suites covering authentication, library management, mathematical functions, persistence, and UI testing. The tests reveal architectural patterns, business logic, and integration points.

## Component Architecture

### 1. Authentication Domain

#### Core Components:
- **LoginServlet**: HTTP endpoint for user authentication
  - Handles POST requests with username/password
  - Returns: "access granted", "access denied", "no username provided", "no password provided"
  - Uses LoginUtils for credential validation

- **LoginUtils**: Business logic for authentication
  - Validates credentials via persistence layer
  - Method: `isUserRegistered(username, password)`

- **RegisterServlet**: HTTP endpoint for user registration
  - Handles POST requests with username/password
  - Returns RegistrationResult with status and message

- **RegistrationUtils**: Business logic for user registration
  - Validates password strength and user existence
  - Methods: `processRegistration(username, password)`, `isUserInDatabase(username)`
  - Password validation includes entropy calculation and strength checks

#### Domain Objects:
- **User**: `{id: int, name: String}`
- **RegistrationResult**: `{success: boolean, status: RegistrationStatusEnums, message: String}`
- **PasswordResult**: `{status: PasswordResultEnums, entropy: double, timeToCrackOffline: String, timeToCrackOnline: String, message: String}`

#### Status Enums:
- RegistrationStatusEnums: SUCCESSFULLY_REGISTERED, EMPTY_USERNAME, BAD_PASSWORD, ALREADY_REGISTERED
- PasswordResultEnums: SUCCESS, TOO_SHORT, EMPTY_PASSWORD

### 2. Library Management Domain

#### Core Components:
- **LibraryUtils**: Central business logic for library operations
  - Methods: `lendBook()`, `registerBook()`, `registerBorrower()`, `searchForBookByTitle()`, `searchForBorrowerByName()`, `listAvailableBooks()`, `deleteBook()`, `deleteBorrower()`

- **Servlet Endpoints**:
  - LibraryBookListAvailableServlet: GET endpoint for available books
  - LibraryBookListSearchServlet: GET endpoint for book search (by id/title)
  - LibraryBorrowerListSearchServlet: GET endpoint for borrower search (by id/name)
  - LibraryLendServlet: POST endpoint for lending books
  - LibraryRegisterBookServlet: POST endpoint for book registration
  - LibraryRegisterBorrowerServlet: POST endpoint for borrower registration

#### Domain Objects:
- **Book**: `{id: int, title: String}`
- **Borrower**: `{id: int, name: String}`
- **Loan**: `{book: Book, borrower: Borrower, id: int, borrowDate: Date}`
- **LibraryActionResults**: Enum with SUCCESS, BORROWER_NOT_REGISTERED, BOOK_NOT_REGISTERED, BOOK_CHECKED_OUT

#### Business Logic:
- Lending requires both book and borrower to be registered
- Books must be available (not currently loaned)
- Input validation for empty strings
- JSON output formatting for list endpoints

### 3. Mathematics Domain

- **Fibonacci Function**: Multiple implementations
  - Regular recursive: `Fibonacci.calculate(n)`
  - Iterative algorithms: `FibonacciIterative.fibAlgo1(n)`, `FibonacciIterative.fibAlgo2(n)`

- **Servlet Endpoints**:
  - AckServlet: POST with parameters `ack_param_m`, `ack_param_n`, `ack_algorithm_choice`
  - FibServlet: POST with parameters `fib_param_n`, `fib_algorithm_choice`
  - MathServlet: POST for basic arithmetic

### 4. Persistence Layer

#### Core Components:
- **IPersistenceLayer**: Interface defining data access operations
- **PersistenceLayer**: Implementation (inferred from method calls)
- **SqlData**: SQL query and parameter management
- **ParameterObject**: Typed parameter wrapper
- **DbServlet**: Database management endpoint

#### Key Methods:
- `areCredentialsValid(username, password)`
- `searchForUserByName(username)`
- `searchBooksByTitle(title)`, `searchBooksById(id)`
- `searchBorrowerDataByName(name)`
- `createLoan(book, borrower, date)`
- `cleanDatabase()`, `migrateDatabase()`

#### Database Schema (Inferred):
```sql

Borrowers: (id, name)
Loans: (id, book_id, borrower_id, borrow_date)
```
