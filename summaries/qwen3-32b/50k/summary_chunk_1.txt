#### **2. API Endpoints & Interfaces**

**Web Application (Tomcat/H2 DB Backend)**:  
All servlets are mapped via the `web.xml` in `src/main/webapp/WEB-INF/`.  
- `/login` (POST): Authenticates a user. Validates credentials, handles password complexity.  
  *Parameters: username, password.*  
- `/register` (POST): Registers a user. Validates password strength and uniqueness.  
  *Parameters: username, password.*  
- `/math` (POST): Performs addition. Rejects non-integers or numbers beyond 32-bit int limits (e.g., 2147483648).  
  *Parameters: item_a, item_b (integers).*  
- `/registerbook` (POST): Adds a new book to the database. Prevents duplicates.  
  *Parameter: book (string).*  
- `/registerborrower` (POST): Registers a new borrower. Prevents duplicate names.  
  *Parameter: borrower (string).*  
- `/lend` (POST): Lends a book to a registered borrower.  
  *Parameters: book, borrower, date.*  
- `/ackermann`/`/fibonacci` (POST): Special mathematical functions from the 'math' domain.

**Database (H2)**:  
- Servlet endpoint `/flyway` resets and migrates the database.  
- Another endpoint `/db/help` allows querying the DB schema (for demo purposes).

**Internal Communication**:  
Uses a Java-based internal web (Tomcat) server, likely via HTTP for inter-component communication. Testing code uses direct database access for integration.

**Desktop App Communication**:  
- Local socket server at port 8000 (implemented in `AutoInsuranceScriptServer.java`) processes automation commands.  
- Commands include `set age`, `set claims`, `click calculate`, and state `get` queries.

#### **9. Critical Considerations for Decomposition**

- **Database Sharing**:  
  Currently shared via H2. Would require service-specific databases or strict schema isolation (e.g., multiple Flyway scripts with namespaced objects).

- **Single Servlet Runner**:  
  All features run through Tomcat in a single container. Decomposition would require launching multiple Tomcat apps (one per microservice) or alternative setups (e.g., Docker containers).

- **Centralized Testing Infrastructure**:  
  While modular, tests assume a unified environment. Decompose would need to test against each microservice independently, possibly using Pact for contract testing.

- **Shared Helper Classes**:  
  `CheckUtils.java`, `StringUtils.java`, etc., could be factored into a shared utility library or moved to cross-cutting concerns.

- **Version Compatibility**:  
  Requires Java 11 for both web app and desktop, as per `docs/ci_and_cd/jenkins_box_guide.txt` and `gradle.properties`. Python and Node.js for BDD/UI tests must be version-aligned across environments.

- **Performance/Security Testing**:  
  These remain as cross-service tests post-decomposition (JMeter for performance, OWASP DependencyCheck for security).
