### **Architectural Summary of Codebase Chunk 3 (Persistence & Library Logic)**

---

#### **Component Overview**
1. **Persistence Layer (`IPersistenceLayer`)**
   - **Responsibility**: Centralized database access for:
     - **Library Management**: Books, borrowers, loans.
     - **User Authentication**: User credentials and registration.
     - **Database Utility**: Schema migration, backups/restores.
   - **Key Methods**:
     - CRUD operations for `Book`, `Borrower`, `Loan`, `User`.
     - `runBackup`, `runRestore`, `cleanAndMigrateDatabase` for schema management.
   - **Dependency**: Uses H2 as a test database (JDBC) in integration tests; likely PostgreSQL in production (via Flyway).

2. **Authentication Subsystem**
   - **Components**:
     - **`LoginServlet` & `RegisterServlet`**: REST endpoints for user authentication and registration.
     - **`LoginUtils` & `RegistrationUtils`**: Business logic for credential validation and password complexity checking.
   - **Key Logic**:
     - Password validation via entropy estimation (library `Nbvcxz`).
     - Authentication checks using `PersistenceLayer#areCredentialsValid`.

3. **Library Subsystem**
   - **Components**:
     - **Servlets**: `LibraryBookListSearchServlet`, `LibraryBorrowerListSearchServlet`, `LibraryLendServlet`, etc.
     - **`LibraryUtils`**: Business logic for book lending, borrower registration, and availability checks.
   - **Key Logic**:
     - Enforces rules like "a book cannot be checked out if already loaned".
     - Maintains relationships via `PersistenceLayer` (e.g., linking `LOAN` to books/borrowers via foreign keys).

4. **Database Schema (Flyway-Managed)**
   - **Tables**:
     - `LIBRARY.BORROWER` (id, name)
     - `LIBRARY.BOOK` (id, title)
     - `LIBRARY.LOAN` (id, book_id, borrower_id, borrow_date)
     - `AUTH.USER` (id, name, password_hash)
   - **Constraints**:
     - Foreign keys (`LOAN.BOOK → BOOK.ID`, `LOAN.BORROWER → BORROWER.ID`).
     - Primary keys on `id` in all tables.
   - **Versioning**:
     - Managed via `FLYWAY_SCHEMA_HISTORY` table.
     - `V1__Create_person_table.sql`: Initial schema.
     - `V2__Rest_of_tables_for_auth_and_library.sql`: Adds authentication and loan tables.

5. **Utilities**
   - **Servlet Helpers**: `ServletUtils`, `StringUtils` for JSON formatting, request handling.
   - **Validation**: `CheckUtils` for null/empty checks and application invariants.
   - **Testing**: `EmptyDataSource`, mocks for `PersistenceLayer` in integration tests.
