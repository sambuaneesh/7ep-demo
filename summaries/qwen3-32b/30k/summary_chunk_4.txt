# Microservice Decomposition Architectural Summary - Chunk 4

## 1. Component Overview
This chunk represents the core persistence layer and database infrastructure for the system. It contains:

### **1.1. Components & Responsibilities**
| Component | Responsibility |
|---------|----------------|
| **PersistenceLayer** | Central data access component handling all database operations for: <br> - Book management (create/read/update/delete) <br> - Borrower management <br> - Loan tracking <br> - User authentication & registration |
| **SqlData** | Encapsulates SQL query templates with parameters, execution strategies, and result mapping functions for type-safe database operations |
| **ParameterObject** | Generic parameter wrapper for type-safe SQL parameter injection |
| **SqlRuntimeException** | Custom runtime exception wrapper for SQL error handling |
| **WebAppListener** | Tomcat ContextListener that initializes database schema on application start |

### **1.2. Key Domain Objects**
- **Books** (`library.book`): Title, ID
- **Borrowers** (`library.borrower`): Name, ID
- **Loans** (`library.loan`): Book ID, Borrower ID, Borrow Date
- **Users** (`auth.user`): Name, Password Hash, ID

## 2. Database Architecture
### **2.1. Database Schema & Tables**
```sql
-- Authentication
auth.USER (
    id serial PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    password_hash VARCHAR(100)
)

-- Library System
library.BORROWER (
    id serial PRIMARY KEY,
    name VARCHAR(100) NOT NULL
)

library.BOOK (
    id serial PRIMARY KEY,
    title VARCHAR(100) NOT NULL
)

library.LOAN (
    id serial PRIMARY KEY,
    book int NOT NULL REFERENCES library.BOOK (id),
    borrower int NOT NULL REFERENCES library.BORROWER (id),
    borrow_date date NOT NULL
)
```

### **2.2. Database Configuration**
- **Database Engine**: H2 in-memory database (`jdbc:h2:mem:training`)
- **Schema Management**: Flyway DB used for:
  - Schema migrations (V1__Create_person_table.sql → V2__Rest_of_tables_for_auth_and_library.sql)
  - Clean/migrate operations
- **Deployment Artifacts**:
  - Schema migration files under `resources/db/migration`
  - Flyway configuration in `PersistenceLayer#configureFlyway`

### **3.2. ORM Implementation**
- **Micro ORM Framework**: Custom implementation using `SqlData` template pattern
- **Key Patterns**:
  - PreparedStatement parameter injection via `ParameterObject<T>`
  - Result mapping via `Function<ResultSet, Optional<T>>` extractors
  - Template methods for DML operations:
    ```java
    executeUpdateTemplate()
    executeInsertTemplate()
    runQuery()
    ```
- **SQL Injection Prevention**: Type-safe parameter binding for common types (String, Integer, Long, Date)

## 5. Key Business Logic
### **5.1. Authentication Workflows**
```java
// Password hashing flow
private String createHashedValueFromPassword(String password) {
    MessageDigest digest = MessageDigest.getInstance("SHA-256")
    return bytesToHex(digest.digest(password.getBytes()));
}
```

### **5.2. Loan Validation Logic**
- Prevents double-checked out books by checking:
  ```sql
  SELECT b.id, b.title FROM library.book b
  LEFT JOIN library.loan l ON b.id = l.book
  WHERE l.borrow_date IS NULL
  ```
- Prevents loan of non-existent books or unregistered borrowers

### **5.3. Schema Lifecycle Management**
- `WebAppListener.contextInitialized()` hooks:
  ```java
  pl.cleanAndMigrateDatabase();
  ```
  - Calls Flyway's `clean()` → `migrate()` sequence
  - Ensures schema is reset on Tomcat restarts

  - Business logic (Utils classes)
  - Web presentation (JSPs)

### **7.2. Technical Frameworks**

- **Flyway**: Database version control with automatic schema migrations
- **Log4j2**: Logging infrastructure

- **Servlet Lifecycle**: Application startup via Tomcat listener hooks
